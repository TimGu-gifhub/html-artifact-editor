## 1. 证据分层

| 层次 | 检查内容 | 能证明什么 |
| --- | --- | --- |
| 纯核心自动测试 | 解析、范围、实体、Unicode、补丁、历史 | 核心输入输出规则；不能证明用户可用 |
| 文件/协议集成测试 | 冲突、备份、路径授权、恢复 | 操作系统行为与权限边界的样例结果 |
| Electron E2E | 打开、选择、草稿、Diff、保存 | 测试环境中的整条链路，不替代原生 IME/安装器人工验收 |
| Windows/Mac 实机 | IME、DPI、权限、窗口、安装器、实际浏览器 | 标明机器与版本的实际使用证据 |
| 维护者真实任务 | 脱敏报告的完整校稿任务 | 产品是否能用，不能从单元测试数推定 |

所有执行记录必须包含 commit、OS/架构、Electron/Chromium 版本、样例 ID、步骤、预期、实际、通过/失败/未测、证据位置。未测不是通过。

## 3. 保存故障与安全用例

| ID | 故障或攻击 | 必须观察到的结果 |
| --- | --- | --- |
| S-01 | 路径 `..`、双重编码、UNC、设备路径、ADS、symlink/junction | 不能读取根外文件；拒绝返回内容 |
| S-02 | 页面伪造 nodeId、offset、路径、旧会话、子 frame IPC | 拒绝请求；高权限能力仍不可见 |
| S-03 | 页面访问 Node/Electron/fs、打开窗口、外部协议、下载、权限 | 全部无扩权；拒绝结果可核验 |
| S-04 | HTTP(S)、WebSocket、localhost/LAN、外部字体、表单、跳转 | 离线策略拒绝；记录目标，不发起网络访问 |
| S-05 | 请求备份、草稿、`.git`、隐藏配置、其他项目 session | 不能读取应用状态及跨项目内容 |
| S-06 | 备份目录无权限、空间不足、备份 hash 不符 | 原 HTML 不变，草稿保留 |
| S-07 | 临时写入失败、替换被占用/拒绝、文件元数据限制 | 原文件完整或进入明确恢复流程，不能先删原文件 |
| S-08 | 各事务节点强制终止后重启 | 用 old/new hash 和 journal 判定；不盲目重复保存 |
| S-09 | 替换前后外部竞争写入 | 冲突或结果不确定，不冒报成功；记录残余竞态 |
| S-10 | 超大文件/DOM/输入、畸形 HTML、快速切换、JS 死循环 | 可取消/终止预览；可信 UI 可恢复；无无限资源增长 |

S-01 至 S-05 在 M1 即建立负向样例，M2/M3 扩充。S-06 至 S-09 是开放覆盖保存的前置条件。S-10 记录限制与超时，不承诺进程能抵挡所有运行时漏洞。

## 4. 样例集

优先自制最小样例，记录每个样例的源码 hash、许可、期望可编辑节点与只读原因。第三方库若用于离线测试，固定版本并保留许可；真实业务文件必须脱敏且由用户明确允许使用，不能上传到公开仓库。

固定语料至少覆盖：纯静态文档、表格报告、嵌套文本、实体/Unicode、混合行尾、中文文件路径、本地图片/字体/CSS、离线 Tailwind/Bootstrap 输出、带 Canvas/ECharts 的只读交互页面、SVG、iframe、Shadow DOM、动态框架页面、缺失 CDN、无效 UTF-8、恶意路径/IPC、10,000 行与上限规模文档。

每个语料可以有“可浏览”与“可编辑”的不同结论。不支持样例的通过标准是**正确拒绝**，不是强行打开编辑。

## 5. 平台矩阵

| 目标 | 本地自动检查 | 人工必需 | 首版状态 |
| --- | --- | --- | --- |
| Windows 10 x64 | 在对应实机或 VM 运行核心/集成，记录实际 OS | 真机或隔离 VM 的安装、路径、IME、DPI、保存恢复 | 待验证 |
| Windows 11 x64 | 同上 | 同上；不能用 Win11 结果代表 Win10 | 待验证 |
| macOS 13+ arm64 | 在 Apple Silicon Mac 本地执行 | Apple Silicon 真机、中文 IME、Retina、权限、DMG/Gatekeeper | 待验证 |
| 其他平台/架构 | 不在本轮发布门槛 | 后续独立提案 | 范围外 |

每次记录实际 OS 版本与 CPU 架构，Mac 需确认 Apple Silicon 及具体系统版本，不能用其他版本代表最低 OS。Electron 相同不能保证跨系统像素一致，字体与原生控件差异按实机评估。所有自动检查本地执行，不设置 GitHub CI 门槛。

## 6. 性能与退出门槛

记录冷启动/热打开、首次选择、悬停、100 条 Patch 保存、峰值内存和关闭后资源释放。每个基准至少 20 次，说明冷热缓存、硬件与样例；报告 p50/p95，不只报最佳值。性能目标见 [PRD](../PRD.md)，首次基准可以调整保护上限，必须记录原因。

P0：数据丢失、越权读写、错误文件覆盖。P1：支持范围内误改源码、保存/恢复失效、核心路径不可完成。MVP 和 Alpha 必须无已知 P0/P1，其他问题有复现及明确限制。自动门槛通过后仍需维护者完成真实任务。
