# 交互后的当前显示与原位校稿

2026-09-11。此补充扩展 [浏览与原位校稿](CONTEXTUAL_EDIT.md)：先在“浏览”中滚动到渐显正文、展开问答或触发本地提交提示，再切换“编辑文字”，可继续看到经过源码核验的这些静态内容，直接点击原文输入。无需把“显示隐藏内容”作为必经步骤。保存仍需复核全部变更和源码 Diff。

## 显示延续合同

- Main 使用当前已核验的 SourceIndex 准备整树计划，不要求面板 ID 或特定框架。最多 5000 个树节点、1200 个 HTML 显示目标、768 KiB 序列化字符；超限返回部分保留，不启动无界扫描或常驻整页观察器。
- 固定隔离 world 1005 按源码核对完整文档的模式、doctype、节点顺序、父子关系、元素名称与命名空间、全部 Text/注释及属性。HTML 仅允许 `class/style/hidden/aria-hidden/aria-expanded` 与源不同，`details` 另允许 `open`；外来命名空间的属性必须全匹配。模板片段、Shadow DOM、脚本新增/删除/改写正文均不能通过这项整树证明。
- 保存后的旧视图只按 Main 已确认的 Text 草稿核对；新的静态视图必须匹配新源码。浏览中的任何 Text、输入框值、脚本数据、路径或 offset 都不进入草稿，也不授予写入权限。
- 源码证明通过后，只读取有限的 `display/visibility/content-visibility/opacity/transform/filter`、伪元素 transform 和 `details::details-content` 的显示状态。transform 限有限矩阵，filter 限 none/有限 blur；不接收 URL、选择器、任意 CSS 或伪元素 content。
- 从浏览离开时，可等待已开始的 CSS transition 最多 1 秒、最多 400 个，再重新核验整树。它不执行页面函数、不快进动画、不等待无限 CSS 动画。超过等待时间只捕获当时能核验的外观，不承诺任意动画最终态。
- 比较前后显示，最多保留 400 个差异元素、256 KiB 规则。Main 生成数字位置 CSS，使用可精确撤回的 author-origin `@media screen` 句柄；不复制 class/style/open，也不改变 DOM 属性。显示已展开问答使用 `::details-content`，原始 `open` 值保持不变。
- 插入后核对随机样式标记及每个保留目标的实际计算属性，再发布状态。原有相邻面板子树证明可独立保留支持区域；整树证明失败或部分属性不可用时明确报告 partial，不把未核验状态称为完整保留。
- 初次从未交互的静态视图进入浏览，不把默认的隐藏渐显状态覆盖到刚开始运行脚本的新视图。后续从校稿返回浏览可使用已核验的临时显示；第一次被 Main 接受的可信鼠标、键盘或滚轮事件撤回样式。页面脚本从新加载的状态继续，不能据此推定原 JavaScript 内存、表单值或全部点击语义已恢复。
- “显示隐藏内容”是另一项文档内检查工具；其开启或显示未知期间不将批量展开样式捕获为页面交互状态。保存或切换的新视图仍按该工具原有合同重置，防止开关显示关闭却残留批量展开。
- 显示读取、插入验证与撤回仍受已有文档身份、输入 owner、离开决定、源版本及关闭等待保护。保存提交后的可选显示失败只报告 partial，不把已核验的 SaveCommit 变成重新保存的理由。

`PresentationState` 只增加可选 `elements`（显示差异元素数）和 `details`（其中显示为展开的问答数），保留 `documentId/panels/status`。这些数值不是可编辑文字数量。旧状态兼容，过期文档不显示。实际输入仍由禁用脚本的新映射和唯一 LiveInputController 接管，原位几何不可用时可使用校稿栏。

## 本地表单演示

部分单文件页面的 `submit` 监听器只负责隐藏表单、显示预置提示。Chromium 的响应 sandbox 禁止表单时，会在发出原生 submit 事件前停止；仅阻止网络不足以让这种本地演示正常工作。相关顺序见 [HTML 表单提交算法](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#form-submission-algorithm)。

交互模式的隔离 preload 因此只转发真实、未取消、启用的 submit 按钮点击：保留原生字段验证和 `noValidate/formNoValidate`，阻止默认提交，发出绑定同一表单/submitter 的合成 `SubmitEvent`。同一表单拒绝同步重入。合成点击、禁用按钮、已取消点击和未通过的字段验证都不会触发转发。

该事件的 `isTrusted` 为 false。它不调用 `submit()` 或 `requestSubmit()`，不收集表单数据、不提供页面 API/IPC，不放开 `allow-forms`；原 CSP、`form-action 'none'` 和网络防护保持不变。监听器内尝试真实 POST 仍被拦截。依赖可信 submit、无按钮隐式提交、直接脚本调用或服务端返回的表单不属于保证范围；校稿模式不安装此转发。

## 保存、打印与后续动态内容

源码只接受受支持静态 Text 的字节 Patch；本次支持的是“原来就在文件里、交互后才显示”的正文。显示状态不写入 HTML、检查点或恢复记录。保存后的当前工作台可继续显示，重新打开和恢复使用文件的初始规则。PDF 也使用原文件打印规则，不自动打印全部折叠项或渐显项。

真正由脚本/框架创建、替换的正文仍只读。后续按以下顺序另行定义任务，而不是在本合同下推定已支持：

1. 用自制动态语料明确框架重绘、异步数据、跨界面定位与可观察失败条件，制定 ADR。
2. 区分“导出当前画面为独立静态副本”与“回写框架/数据源”。前者必须是明确标记的新产物，不能覆盖原应用；后者需要来源适配和稳定的源码/数据证明，不能通过 DOM 序列化或文本搜索获得权限。
3. 在选定产物和来源合同后，再接入原位输入、复核、冲突、恢复及跨界面回归。本阶段未实现这两个导出/回写能力。

## 执行证据

`npm run test:product-view` 用自制 HTML、真实产品 React/IPC/隔离 Preview、原生点击与 Windows 保存，覆盖渐显、问答、本地提示、原位聚焦/Unicode/实体、保存前零写入、全选复核/Diff/精确全文件字节、保存后显示、原打印规则、重开原交互与脚本改字拒绝。`test:security` 验证真实点击可触发合成本地事件，字段验证/取消/禁用按钮受尊重，监听器真实提交仍为零网络连接。模型分工、实际执行结果和未验收项见 [HAE-009](implementation/HAE-009.md)。

原生选择和确认由 Main 测试回调提供。真实 Windows IME、OS 鼠标、多屏 DPI、Windows 10、读屏及维护者 M2 校稿保持独立验收，不能由以上自动结果推定完成。
