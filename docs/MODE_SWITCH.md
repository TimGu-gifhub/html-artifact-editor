# 产品内静态校稿与脚本只读预览

2026-09-10 实施合同。沿用 PRD 的两种模式和方案 B，不增加可写内容种类或网络权限。Main、可信 IPC 与 Kimi 产品控件已接通，六组真实产品自动回归及分工记录见 [HAE-008 第三阶段](implementation/HAE-008.md)。维护者人工验收仍待执行。

- 正常打开和恢复进入静态校稿。可信控件以 documentId、最新 stateRevision 和固定 mode 枚举请求切换，不接受路径、URL 或页面数据。
- 切换前排空实际校稿窗口的输入。组词、忙碌、清理或结果不确定时拒绝。Main 在运行脚本之前处理旧草稿的取消、放弃或独占另存决定；失败保留旧文档。
- 脚本只读文档使用独立隔离 session 和原有根目录授权，只加载源文件原始字节。不建立源码映射、输入控制器、草稿、历史 Worker 或写入端口；快照明确提供 mode=interactive、input=null、persistence=null。动态 DOM 不得进入保存、Diff、备份替换或草稿 PDF。
- 两个方向都创建新文档身份和原生视图。准备、文件版本或试挂载失败保留旧文档。成功后撤销旧视图权限并完成清理；清理不确定时继续阻止后续危险操作。
- 没有净变更的静态文档，若此前已有编辑，先确认最新干净检查点，再将私有完整历史保留到只读文档。未经编辑的初始 revision=1 没有持久化序列，往返不写空检查点；第一次实际编辑才能开始入队。返回时重新验证同一文件版本，重建静态源码映射与历史；不接受旧 offset 或动态 DOM。放弃/另存后切换使用新的干净历史，不把放弃的草稿恢复回来。
- 已进入只读后若文件被外部修改，返回校稿拒绝迁移旧历史；用户可以通过明确打开操作选择新的文件版本。预览、取消和模式切换均不自动覆盖 HTML。
- 只读仍可查看诊断、打开文件/目录、切换入口和关闭。编辑、历史、保存、整份备份替换和草稿 PDF 由 Main 以 READ_ONLY_MODE 拒绝，界面同时说明需返回静态校稿。浮窗归属保留，空输入不产生替代草稿。已有 PDF 快照仍可查看或导出，并标明属于先前文档。

新增 `test:product-mode` 覆盖两个方向、初始空历史、干净 Redo、保存空 Text 后的 Undo/Redo、脏草稿三种决定、复制失败、组合态/浮窗/重复请求、版本冲突、只读命令拒绝、离线/根边界与完整字节保护。另有八项 Main 单元反例覆盖迟到输入/撤销、试挂载回滚、未知退役及失败清理；这些 fixture 不代替真实文件或产品证据。OS 输入法和选择器人工验收保持独立。

2026-09-11 补充：产品“浏览 / 编辑文字”切换可保留经过新源码逐节点核验的预置 hidden/CSS 面板和滚动位置。延续发生在新映射建立后、Workspace 发布前；只使用屏幕样式，动态 DOM、历史和写入权限仍不迁移。显示读取有界，未确认结果拒绝切换；核验后的保存也可延续面板；重新打开/恢复仍使用原始显隐。返回浏览时以临时屏幕样式保留当前面板，第一次被 Main 接受的可信交互撤回样式以恢复原页面交互。精确支持范围、部分结果及独立原生边框/小窗合同见 [浏览后就地校稿](CONTEXTUAL_EDIT.md)。

同日后续补充以完整源树证明延续渐显、有限 CSS 显隐、展开问答和本地提交提示；不要求相邻面板 ID。第一次浏览不继承初始隐藏的渐显状态，返回浏览的临时样式也接受可信滚轮撤回。原生表单仍禁止导航/联网，仅为本地演示转发未取消的真实提交按钮点击。验证预算、合成 submit 语义与未支持的框架状态见 [当前显示补充](CURRENT_VIEW.md)。
