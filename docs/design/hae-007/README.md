# HAE-007 三套可运行视觉候选

状态：候选稿，**尚未选稿，未实现产品 UI**。本目录是完全离线、零依赖的 HTML/CSS/JS 视觉原型，供维护者比较三个方向后选择其一；选定前不据此修改产品代码（产品技术栈仍为 React/TypeScript）。原型不读写文件、不解析 HTML、不联网，仅操作页面内自制报告 DOM。

## 打开方法

无需构建与依赖安装，直接用浏览器打开：

```text
docs/design/hae-007/index.html
```

支持 `file://` 直接运行（双击即可）。`report.html` 是同一份脱敏报告的独立静态样例，供对照“报告排版不随方案改变”。

### URL 参数

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `scheme` | `a` / `b` / `c` | 选择视觉方案，默认 `a` |
| `state` | `editing` / `readonly` / `unsaved` / `conflict` / `narrow` | 初始演示状态，默认 `editing` |
| `width` | `narrow` | 强制窄窗口布局（可与任意 state 叠加） |

示例：`index.html?scheme=b&state=unsaved`、`index.html?scheme=c&state=conflict&width=narrow`。顶部演示控制器的切换会同步到 URL（`replaceState`，不读盘）。实际窗口宽度 < 1024px 时自动进入窄布局（即最小候选尺寸 960×640 也以窄窗口形态运行）。

## 同一份任务（三个方案共用）

- 报告：标题“2025 年度报告”、副标题日期、三行以上表格与两个段落，内容固定且脱敏。
- 校稿任务：标题年份 2025 → 2026；修正三处表格文字（“同比增涨”→“同比增长”、“研发投人占比”→“研发投入占比”、“第四季渡”→“第四季度”）；演示“取消一次未应用输入”；查看四条变更（副标题日期为可选第五目标，不计入主截图的四条）。
- “未保存 / 冲突”演示状态预置的正是这四条已应用变更，保证主截图前后一致。

## 三个方案的取舍

| | 方案 A · 预览优先 | 方案 B · 校稿侧栏优先 | 方案 C · 变更复核优先 |
| --- | --- | --- | --- |
| 空间分配 | 预览最大，右侧校稿栏仅 300px，克制轻量 | 右侧侧栏 420px，预览让位 | 预览约 55%–60%，右列 380px |
| 变更列表 | 默认隐藏，点“变更”按需抽屉打开 | 内嵌在侧栏下方（约 1/3 高），随时可见 | 右列上半部大卡片展示改前/改后，最突出 |
| 输入区 | 与侧栏同宽，紧凑 | 最宽敞：原文、输入、应用/取消、提示完整展开 | 右列下半部紧凑输入 |
| 适合场景 | 以浏览页面为主、偶尔改字 | 连续逐段文字校对 | 改完逐条复核、交付前检查 |
| 代价 | 复核变更多一步打开 | 预览宽度明显收窄 | 输入区与预览都略受挤压 |

三方案共用同一套设计令牌、组件与交互逻辑，仅网格布局、面板宽度与变更面板形态不同；报告本身排版完全一致。

### 字号与字体

系统字体栈（`Segoe UI / system-ui / 微软雅黑 / 苹方` 等），无网络字体。界面正文 13px；面板标题 13px 半粗；提示 12px；状态栏 12px；对话框标题 15px；报告内 h1 26px、h2 17px、正文 15px、表格 14px。

### 焦点与键盘

- 所有可交互元素有 2px 蓝色 `:focus-visible` 外描边（offset 2px）。
- 对话框有名称（`aria-labelledby`）、`aria-modal`、Tab 焦点限制在按钮组内，关闭后焦点回到触发元素。
- 变更抽屉（方案 A 与窄窗口）打开时带 `role="dialog"` 与名称，Tab 焦点限制在面板内；Escape、遮罩、关闭按钮关闭后焦点回到“变更”触发按钮。关闭时面板设为 `inert` + `aria-hidden` 并移出视口，其中的“定位/撤销此条”不可再被 Tab 聚焦。“⋯”更多菜单关闭同样回焦触发按钮。
- 快捷键：Ctrl+O 打开（演示）、Ctrl+S 保存（演示）、Ctrl+Shift+S 另存（演示）、Ctrl+Z 撤销、Ctrl+Y / Ctrl+Shift+Z 重做、Ctrl+Enter 应用、Esc 逐层退出（菜单 → 取消未应用输入 → 关闭抽屉 → 取消选择）。
- 输入框内 Ctrl+Z 交给浏览器本地撤销；Enter 在 textarea 换行；粘贴沿用 textarea 原生行为（本身就是纯文本，不拦截、不破坏浏览器输入撤销，不使用 contenteditable，不接受 HTML）。
- IME：`compositionstart` 至 `compositionend` 期间，应用级快捷键（Esc / Ctrl+S / Ctrl+Enter / Ctrl+Z 等）与动作入口（应用、取消、选择/模式切换、撤销/重做/撤销此条、打开/保存等按钮、对话框按钮与对话框 Escape）统一忽略，组合结束后不重放旧指令。
- 无未应用输入时，应用级撤销/重做把输入框同步到新的当前草稿；有未应用输入时，撤销/重做/撤销此条先走“应用后继续 / 放弃输入 / 继续编辑”保护确认。同一目标的再次点击/双击保留输入（双击聚焦输入框），只有切到另一目标才触发保护。
- 输入旁固定提示“换行显示取决于原页面样式”。

### 状态清单

| 状态 | 表现 |
| --- | --- |
| 正常编辑 | 可悬停/单击选择文字，输入、应用/取消、撤销/重做可用 |
| 只读 | 顶部只读横幅 + 文字原因（“此文件不是可安全修改的 UTF-8，已只读打开”）；输入、应用、保存关闭；预览目标不可选 |
| 未保存 | 预置四条已应用未保存变更；文件名旁“未保存”徽标；变更计数 4；状态栏提示 |
| 冲突 | 红色横幅，正文“文件已被其他程序修改，本次尚未覆盖。”，动作“另存草稿 / 重新加载 / 取消”；重新加载先确认放弃草稿，不暗中清空 |
| 窄窗口 | 单列；变更面板抽屉化；次要动作（打开、模式切换、另存）折叠进“⋯”；保留预览与输入 |

另有跨状态概念：**未应用输入**（“尚未应用”徽标、目标虚线框、失焦保留）、**已应用未保存**（变更列表、工具栏计数、报告内琥珀色标记）、**已保存**（原型不真实写盘，仅以演示对话框说明时机）。校稿栏中三者明确分开：“文件原文”始终显示磁盘文件的文字（如“2025 年度报告”），输入框显示已应用草稿（如“2026 年度报告”），“尚未应用”徽标标记未应用输入。无变化的应用不产生变更；恢复原文移除净变更；取消不生成历史。

### 静态校稿 vs 交互预览（只读）

切换“交互预览（只读）”：顶部蓝色横幅说明只读；编辑入口关闭；页面出现一行“脚本生成”的演示动态内容以区分两种模式；既有草稿与选择保留，切回静态校稿即恢复。模式/目标切换时若有未应用输入，先弹出“应用后继续 / 放弃输入 / 继续编辑”。

## 已实现的内存演示

- IME 组合期间动作入口的统一忽略（代码路径已实现，真实输入法未验收）。

## 演示行为（非产品能力）

- “打开 / 保存 / 另存为”只显示标注“演示：…”的对话框，不读盘、不备份、不下载、不改变状态。
- “另存草稿 / 重新加载”为演示反馈；重新加载确认后仅重置内存状态。
- 状态栏“资源：2 项外部资源被阻断”打开的是虚构示例清单，不联网。
- 演示控制器的五种状态切换只重排界面与预置数据，不代表文件事务。
- 原型不展示源码映射、节点 ID、路径偏移等实现细节；不实现 HTML 解析、补丁、IPC、持久化。
