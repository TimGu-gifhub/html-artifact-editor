## 实际执行范围

新增 `npm run test:product-acceptance`，使用正常产品的 React、preload、可信 IPC、Main 工厂、Workers、隔离 Preview、固定目录持久化及 Windows ReplaceFileW。父进程协调四个真实 Electron Main 进程；编辑、复核、恢复、撤销、备份和另存均点击实际产品控件。Main 读取状态只用于等待和核对，不直接调用核心编辑或保存方法替代产品操作。

测试报告为自行编写的静态 HTML，含 UTF-8 BOM、CRLF、中文、Emoji、字符实体、保留注释、外部 CSS 和原有脚本。五处修改为标题、日期及三个表格单元格；未改段落、标签、属性、脚本、换行和资源均通过独立完整字节比较保护。

| 产品流程 | 已执行的断言 |
| --- | --- |
| 强杀与恢复 | 五处实时修改达到准确的最新持久化版本后，父进程实际终止 Main。新进程从“恢复草稿记录”重新授权；取消选择和选错同内容文件都不安装草稿、不写 HTML。正确恢复使用新 UI 文档身份及原检查点序列，五处文字和净变更正确 |
| 复核保存与独立重开 | 取消源码 Diff 保留五处草稿且原文件不变；重新全选复核、确认 Diff、原生保存后，完整文件字节符合独立预期。已安装的 Edge 在独立进程和新 profile 中重开文件，五处内容正确、原脚本执行且外部 CSS 生效 |
| 跨保存历史与整份备份恢复 | 正常原生关闭后进程退出 0；再启动从产品控件恢复已保存的干净历史。Undo 只改变草稿，经第二次复核保存后才写回文件；Redo 仍可用，回到保存点后取消备份恢复不写文件，单独确认恢复则还原整份原始 HTML 并建立干净历史。Edge 再次重开核对原文 |
| 外部冲突与另存 | 另一个父进程在文档已打开且有草稿时改写源文件。产品保存显示 `FILE_CHANGED` 并保留草稿；“另存草稿”创建独占新文件，外部改写后的原文件完整保留。明确放弃当前草稿后，正常关闭实际退出 0 |

恢复后的产品列表和 Preview 分别截取真实帧并检查；主渲染器截图不包含原生 WebContentsView，因此两张图片分别表示界面与文档，不将空白占位区域当作页面内容。测试窗口实际显示，避免隐藏窗口返回旧合成帧；截图仅辅助核查，不代替产品交互和字节断言。
