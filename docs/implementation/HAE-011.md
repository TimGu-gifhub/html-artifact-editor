## 第六阶段：冻结源码 Diff 与保存确认

## 第七阶段：逻辑历史与已保存空 Text 的反向来源证明

清空后保存的 Text 通过新基线重建：重新解析最初/当前字节，核对完整树和所有 Text 外字面片段，仅已知清空目标可缺席。使用新解析范围与逐字节匹配的间隔推导当前空边界，再校验 UTF-8/code-unit 对应；生成新源身份和上下文，禁止直接复用旧 offset。仅带完整内部 lineage 且重新证明成功的空目标允许零长度 Patch；普通伪造空范围仍拒绝。原 Patch 的编码、输出上限、未改字节和重解析语义验证继续执行，Draft/Diff Worker 也重新构建该证明。

历史记录包含完整操作链、游标、独立 savedValues、修订及最初/基线/候选 hash，不含路径、可执行范围或 DOM 序列化。记录最多 1000 个操作和目标，方向文字各受 64 KiB UTF-8 限制；8 MiB 逻辑预算含任意游标保存点的预留，达到上限拒绝新操作，不静默裁掉历史。现有 v1 草稿格式无法承载它，Main 存储在创建锁/文件前以 DRAFT_HISTORY_UNSUPPORTED 拒绝带 lineage 的候选，避免丢掉 Undo/Redo 后误报持久化。完整合同及调用顺序见 [HISTORY](../HISTORY.md)。
