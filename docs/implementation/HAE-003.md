# HAE-003 静态源码映射交付记录

日期：2026-09-09。任务：[Issue #3](https://github.com/TimGu-gifhub/html-artifact-editor/issues/3)。验证基线：`0641e7152377263b669d68f39f72d84c8e2aa4ed` 加本次 HAE-003 差异；最终提交与执行状态记录在 Issue。对应决策：[ADR-011](../DECISIONS.md)。

静态校稿的 Text 对象可以在完整树核对后关联到唯一原始字节范围；重复文字不混淆。预览仍只读。没有草稿修改、字节 Patch 拼接、覆盖保存、产品侧栏或安装包，不能据此宣称 M1 最小链路或 M2 完成。

## 实施范围

- `src/core/parser`：严格 UTF-8、BOM 修正、UTF-16 到字节边界、parse5 索引、连续/不重叠范围和上下文校验。原始字节只复制，不规范化；返回的字节副本不能改变基线。核心不依赖 DOM、Electron 或文件系统，SHA-256 实现由 Main 注入。
- `src/contracts`：预期规范化树与选择消息。来自预览的消息只包含身份、递增 revision、nodeId/null 或固定状态；扩展的 path、offset、text 字段拒绝。没有保存命令。
- `src/main/parser`：单次 worker 解析，5 秒期限，5 MiB 输入、100,000 节点、256 层限制；V8 old/young heap 256/32 MiB、栈 8 MiB。取消/超时等待 worker 实际终止。堆限制不包含所有外部内存，不是进程级硬限制；并未声称完成内存耗尽或性能验收。
- `src/preview/node-registry` 与隔离 preload：核对整树并维护 WeakMap<Text, nodeId>，无页面桥、源码标记和序列化写回。观察 document 与 template.content；绑定前也检查 DOMContentLoaded 后的变更。任何已观察到的外部 childList/characterData/attributes 变化使整张映射失效。
- Main 核对真实 sender、session、主 frame、完整 URL、documentId/baseHash/generation、单调 revision 和已知可编辑节点。关闭/切换释放监听器；过期选择不可用于新预览。
- `npm run preview` 增加开发终端选择诊断，输出核验的编号/版本/字节范围。交互入口拒绝创建映射。产品 React/UI 文件未修改，按既定职责由主开发代理实现核心、安全和集成；没有将本次工作标为 Kimi 前端产物。

parse5 [解析选项](https://parse5.js.org/interfaces/parse5.ParserOptions.html) 与 [位置类型](https://parse5.js.org/interfaces/parse5.Token.Location.html) 是基础 API，字节转换、范围证明与 Chromium 对照是本项目实现。parse5 使用 scriptingEnabled=true；CSP 禁止脚本执行不等于 noscript 按 scriptingEnabled=false 解析。新增运行依赖仅 parse5 8.0.1 及其 entities 8.1.0，精确锁定；其 MIT / BSD-2-Clause 原始声明由 licenses 工具复制。

## 实际支持与拒绝

表中“支持”仅指静态映射实验，不代表保存能力。

| 自制样例 / 类型 | 结果 | 依据 |
| --- | --- | --- |
| repeated：十处相同中文/Emoji/实体文字，重复 id | 支持 | 十次实际点击对应十个不同 nodeId 与源码范围 |
| nested：span/strong 嵌套、注释分隔的相邻 Text、br | 单片段支持 | 全树顺序与 Text 值相同，不合并父元素文字 |
| 隐式 tbody | 支持 | 比较真实插入后的树，隐式元素不作为字节范围 |
| entities、pre-leading-newline | 支持 | BOM、组合字符、Emoji、NBSP、实体与 CRLF/CR/LF，含 pre 首换行消费规则 |
| noscript | 只读其子树 | 按原始文本语义核对，外部普通段落仍可映射 |
| script/style/title/textarea/xmp 等特殊上下文 | 只读 | 普通 Text 编码器不能借用于特殊解析上下文 |
| form/select/button 等表单子树、contenteditable | 只读 | 避免表单当前值和页面编辑状态混入源文本 |
| template、SVG/MathML、foreignObject、Canvas 后备内容 | 只读 | 虚拟 fragment/外来命名空间或特殊上下文 |
| foster：表格外移文本合并且包含单元格范围 | 只读两侧 | 合并 Text 不连续，且范围覆盖其他 Text，不能挑一个赢家 |
| adoption：格式化元素纠错克隆 | 整页只读 | parse5 可无 onParseError；额外检测重复元素源位置 |
| parse-error：重复属性，另含 NUL 单元样例 | 整页只读 | 解析错误；不将纠错结果冒充原始来源 |
| no-doctype | 条件支持 | 缺少 doctype 单独允许，必须核对 BackCompat/CSS1Compat |
| 声明式 open/closed Shadow DOM | 整页拒绝映射 | Chromium 树与 parse5 不一致或含 shadow root |
| CSS 生成文字或其祖先下的 Text | 不开放选择 | 包括 ::before/::after/::marker；保守防止伪元素覆盖与 caret 吸附误认 |
| 跨多个 Text 的浏览器选区 | 清除当前选择 | 不构造跨标签操作 |
| JS 交互视图 | 不创建映射 | 即使渲染相同文字也不接受来源推断 |

静态保证依赖 HAE-002 的页面脚本禁止和隔离前提。没有扩展到能任意执行脚本的 DOM、闭合 shadow root 运行时操纵或外部浏览器扩展环境；后续支持扩展需新的证明。

## 执行证据

环境：Windows 11 x64（Windows_NT 10.0.26200），开发 Node 24.14.1、npm 11.19.1；Electron 44.2.0、Chromium 152.0.7977.76、内嵌 Node 24.20.0。仅使用仓库 MIT 自制样例；没有用户 HTML、外部业务数据、在线服务或 GitHub CI。

| 本地命令 | 实际结果 |
| --- | --- |
| `npm run check` | 四套 strict 类型、27 个源文件边界、79 项单元测试、七目标构建、6 组内置冒烟、10 组安全、10 组映射及 62 项许可证清单通过 |
| `npm run test:mapping` | 真实 WebContentsView、隔离 preload 与 worker，25 份 HTML 样例 hash 前后相同 |
| `python tools/check_docs.py` | 文档、链接与 backlog 一致性检查；最终数量见 Issue 提交记录 |
| `git diff --check` | 无空白错误 |

`test-results/mapping.json` 保存版本、commit/工作区、步骤组、25 份样例 hash 和运行时长。点击用 `WebContents.sendInputEvent`，真实坐标来自测试进程测量；测试里的 selector 仅找测试目标，生产映射不接受 selector 授权。`mapping-repeated.png` 只是渲染辅助，不能替代动作断言。源码与测试见 [核心用例](../../tests/unit/source-index.test.mjs)、[UTF-8 用例](../../tests/unit/utf8.test.mjs)、[Electron 实验](../../tests/mapping/main.ts) 和 [共享语料](../../tests/fixtures/mapping/cases.ts)。

主要反向检查：相同值赋值、相同文字 clone、移走再放回、修改后还原、splitText/normalize、属性、注释和 template 变更均失效；绑定前相同值赋值也拒绝。旧世代、旧选择、未知编号、扩展路径/偏移字段、伪 frame 和合成 click 拒绝。宿主测试代码注入 DOM/IPC 是为了故障验证，未向页面开放这些能力。

真实 worker 执行了预取消、运行中取消、无效编码和超深树拒绝、10,000 行索引；另在被忽略的独立测试目录写入故意挂起/抛错的 worker，验证 5 秒超时终止与错误返回。没有修改生产 worker 的安全开关。原有安全回归仍观察到 loopback 服务器零连接。

探索中首次纯核心检查发现 `Buffer.slice()` 会共享输入内存，已改为显式 Uint8Array 复制并测试调用者及返回值均不能改基线；foster 样例还证明单元格位于合并范围内，因此将重叠双方只读，而非只拒绝合并 Text。首轮完整 Chromium 树策略通过，后续复核收紧伪元素与跨 Text 选择，并重跑对应真实实验。没有使用整页序列化降级。
