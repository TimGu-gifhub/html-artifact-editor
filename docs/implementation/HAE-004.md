# HAE-004 纯字节 Patch 交付记录

日期：2026-09-09。任务：[Issue #4](https://github.com/TimGu-gifhub/html-artifact-editor/issues/4)。验证基线：`098a35174a34c8bcb77bd2a801887a7bbbcb8bbd` 加本次 HAE-004 差异；最终提交见 Issue。决策：[ADR-012](../DECISIONS.md)。

核心现在能从冻结源基线生成纯文本补丁与完整候选字节，验证目标值、整树结构和范围外字节不变。多处变长、同节点连续修改、清空、恢复基线和无变化均使用原始 offset。非法或过期请求失败时保留上一份候选。

应用入口仍只读；本节点没有接入产品侧栏、live DOM 草稿、文件覆盖、备份、冲突、恢复、撤销历史或保存点。测试创建的候选文件不是应用 Save，也不代表 M1 最小闭环或 M2 验收完成。

## 实际 API 与边界

实现：[纯核心 engine](../../src/core/patch/engine.ts)、[编码规则](../../src/core/patch/encoding.ts)、[源索引](../../src/core/parser/source-index.ts)。没有新增依赖，也没有 DOM、Electron、Node 或文件系统导入；SHA-256 由可信宿主注入。

| API / 数据 | 行为 |
| --- | --- |
| createPatchEngine(SourceIndex, hash) | 重新解析原字节，核对 hash、全文、源树、节点范围与上下文；持有独立不可变基线 |
| engine.apply(TextChange) | 精确身份/baseHash/nodeId/expectedText/newText；expectedText 必须等于当前候选文字。全部验证成功后才更新状态 |
| engine.candidate | 冻结的身份、baseHash/resultHash、净 patches 与 bytes 副本；调用者不能改坏内部候选 |
| buildPatchCandidate(source, patches, hash) | 内部调用方也不能自行扩展范围或替换原始编码字节；与权威节点和确定编码逐项一致才接受 |
| TextPatch | 原始范围/旧片段 hash/上下文/基线旧值、新值、换行风格及 pre 首 LF 补偿信息；每节点最多一份 |

核心身份不能替代 Main 的 Preview 来源、主 frame、generation 和选择 revision 校验。后续交互应在可取消任务中调用同步核心计算；当前未实现异步编辑调度或 I/O 事务。

## 编码、空文本与候选验证

新输入拒绝 NUL 和非法代理项，CRLF/CR 统一为逻辑 LF；只编码 `&`、`<`、`>`，不插入 HTML。每节点新文字最多 64 KiB UTF-8，最多 1,000 个净 Patch，候选最多 5 MiB；分配最终输出前验证大小，累计编码替换字节也有限额。

目标原片段只有一种换行时沿用该风格，否则按文档计数，平局取 LF。mixedLineEndings 标记目标混合行尾的重新编码。范围之外的 BOM、混合行尾、空白、实体拼写、注释、属性及 script/style 字节保持不变。无变化或恢复基线值直接取消净 Patch，避免无意义地重写原实体。

pre/listing 的第一个 LF 会被 HTML 解析器消费。实验还发现，连续多 LF 时 parse5 的源范围可能包含被消费的 LF；单 LF 后接内容时可能不含它。只在父标签、首子节点与 startTag.endOffset 共同证明的上下文中设置 consumesLeadingLf，按消费一次核对原片段；新值以 LF 起始时补一个会被消费的换行。已经在目标范围外的前缀原样保留，不插入注释、标签或零宽字符。真实 Chromium 已覆盖原始 LF、CRLF、数字实体、注释前缀和 listing。

候选重解析允许指定 Text 值变化与清空后 Text 消失，重映射比较用的父索引；其他元素、属性、注释和文字序列严格相同。新目标仍必须具备源映射证明。表格空白改成会被移到表格外的文字、引入解析错误或失去证明的候选会被拒绝。JSON 树仅用于比较，输出始终来自原字节片段拼接。

内存净 Patch 清空后继续输入仍绑定原范围；A→B→C 合为 A→C，A→B→A 得到原字节。保存后基线重建、空节点的反向操作和历史由后续任务完成，不复用旧 nodeId 猜测。
