# 保存故障时保全草稿副本

日期：2026-09-12；HAE-010。原文件保存返回 unknown、需要审查的 failed，或已经 committed 但新基线重建未完成时，原草稿必须保持冻结。工作台原有“另存草稿”入口现在可以保全这次 Save 使用的已确认候选；成功另存不解除原故障，也不把它改记为保存成功。

## 数据与权限

- [DraftSession](../src/main/draft/session.ts) 只在原文件 Save 进入保护状态时，保留同一个已确认、不可变的 PatchCandidate 引用。字节来自原始文件及已核验静态 Text 补丁，没有页面序列化、动态文字或新增的写入定位方式。
- 普通空闲草稿沿用原另存流程；冻结状态的例外只属于上述原文件 Save。Preview Apply、历史切换或恢复结果未知时，不因存在 uncertainCandidate 就获得该例外；整份备份恢复的离开冻结也未开放。
- `InputSnapshot.canSaveCopy` 表示允许创建独立副本，不再隐含允许覆盖原文件。Workspace 的 canSave 另外要求 draftPhase=idle；执行时仍核验原 Save 报告、文档身份、输入/草稿修订和最新 Diff 复核。
- 只使用 Main 已授权的 [NewFileWriter](../src/platform/new-file.ts)：HTML 必须位于原入口同一目录，独占创建并回读核验；已有文件（包括原 HTML）、链接或越界位置拒绝。没有覆盖副本、自动改名或复制资源的捷径。
- 不改变原候选、基线、逻辑修订、Undo/Redo、Save 报告或 retainedSave，不排队新检查点、不结束旧历史，不移除锁、备份、候选、日志或其他证据。

## 输入与结果

工作台仍先排空实际输入 owner。Main 的 action 排空回执可接受同一文档、同一 owner、准确 Save 故障报告下的可保全候选；组合输入、未应用输入、owner 丢失或文档变化均拒绝。不同用途的并发排空不能共用成功回执。排空只证明输入已确认，关闭、停靠、模式切换、历史、PDF 和 Save 的独立保护继续执行。

原位、浮窗与主栏输入按 uncertain/closed 草稿状态冻结，已有文字保留在同一个只读 textarea，可聚焦、选择和复制。点击另一段文字只保留待切换意图；不自动 begin/change/apply/resolve，也不通过 Escape、重试或还原本段修改冻结输入。干净 owner 可确认已排空，未应用、缓冲、组词、失败和在途输入继续拒绝；不能清空状态换取成功。正常 preparing/applying 仍使用原实时输入缓冲。提示只在 Main 明确允许保全原 Save 候选时提及另存，不把 Preview/历史不确定或关闭状态混称为保存失败。

另存选择器和写入期间互斥，重复请求不产生第二次选择/写入。取消选择或选择器失败不写文件；选择器被撤销、原文档离开或关闭后返回的路径不能启动写入。已接受的独占写入等待同一实际结果。

| 副本结果 | 原保存故障与后续操作 |
| --- | --- |
| created | 副本字节已核验；原 Save 仍冻结，可按需再次显式选择新文件名 |
| cancelled / 已知 failed | 源文件与原事务证据不变，保留原冻结；可显式重新选择合法的新目标 |
| unknown / writer 异常 | 同时保留原 Save 与副本路径/hash/结果证据；禁止重复另存或覆盖，不删除可能已经创建的文件 |

真实产品路径覆盖原位输入、复核 Diff、故障后的对话框/横幅另存、取消、原文件目标拒绝及新副本独立 Edge 重开。完整字节、原 CSS 和全部私有证据由独立测试进程核对。执行结果见 [HAE-010 第九阶段](implementation/HAE-010.md)；这不是人工 IME、原生对话框或 M2 整体验收。

本阶段不提供活动故障会话的解除冻结、关闭放行或通用解锁；保存事务与后续明确处置仍遵守 [保存协议](SAVE_PREPARATION.md)、[统一会话](WORKSPACE_SESSION.md) 和 [产品中断检查](INTERRUPTION_WORKFLOW.md)。
