# 开源与发布计划

## 当前发布范围

本次发布的是公开的 MIT 规划仓库，包括规格、任务、贡献入口与文档检查。没有应用安装包或可用性验收结果，因此不创建应用版本标签和二进制 Release。

## 版本安排

| 版本 | 发布内容 | 门槛 |
| --- | --- | --- |
| 实验构建 | M1 的最小链路 | 显示实验标签；事务未具备前仅另存到新文件 |
| MVP 预览构建 | M2 Windows 校稿流程 | 自动门槛 + Windows 维护者真实任务 |
| Alpha | M3 有证据的平台构建 | 固定样例、安装/实机验证、签名状态明确 |
| v1.0 | 稳定文本产品 | M4 真实任务与全部正式分发门槛 |

版本命名在实现首个应用包时固定；不因路线图完成日期自动打 tag。

## 平台与产物

目标产物为 Windows x64 安装程序和 macOS arm64 DMG；Mac Intel、Windows ARM、Linux 延后。Windows 10 和 11 分别验收；Mac 最低版本与当前稳定系统分别记录可用设备测试情况。

开发构建可未签名，但下载说明必须明确签名状态与限制，不能教用户全局关闭系统安全功能。正式分发计划包含 Windows 代码签名、Mac Developer ID 签名与公证。凭据、证书、付费计划和设备由维护者准备，均不提交仓库。实际流程实施时参照 [Electron 签名文档](https://www.electronjs.org/docs/latest/tutorial/code-signing)。

## 发布门槛

- 固定 Electron/Chromium 与依赖版本，重新核验安全更新和最低 OS 范围。
- 对目标 commit 完成核心、文件集成、预览负向测试与 E2E；无已知 P0/P1。
- 每个宣称支持的平台都有 [测试模板](TEST_PLAN.md) 所要求的实机证据；未测目标不写“已支持”。
- 验证安装、首次启动、打开文件、修改/取消、保存/冲突、备份恢复、卸载后数据保留/清理行为。
- 扫描依赖许可与打包内容，保留 Electron/Chromium 和其他依赖声明；不包含测试用户内容或凭据。
- 生成校验和、依赖/组件清单、变更说明、已知限制和恢复说明；所有文件对应同一 commit。
- 用干净环境重新下载产物，核验校验和、签名、公证与主路径。
- 维护者复核产物和风险后才发布正式版本；不会自动购买签名服务或启用云同步/遥测。

## 仓库协作设置

使用公开 repository、MIT LICENSE、Issues、里程碑、bug/feature 模板与 PR 模板；初期关闭不需要的 Wiki。默认分支为 main。当前 CI 只校验文档，应用代码加入后再追加真实构建/测试作业。

在构建检查稳定后再配置所需分支规则与合并门槛；不设置不存在的 required check 或无人可完成的人工审核条件。贡献者与维护者都应只提交相关文件，保留其他并行工作。

## 隐私与安全反馈

恢复数据、日志和备份默认留在本地；没有自动上报。问题反馈使用脱敏最小样例。安全问题优先使用仓库的私密漏洞报告入口，详情见 [SECURITY.md](../SECURITY.md)。

开源代码和文档不意味着用户打开的 HTML 也要公开；许可证和用户数据分别处理。
